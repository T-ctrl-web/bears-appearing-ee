## 三、Bug 报告

### Bug #1 ｜ emoji 字段未经 HTML 转义（安全/XSS）

| 项 | 内容 |
|----|------|
| 严重等级 | **P1 严重** |
| 类型 | 安全 / 一致性 |
| 位置 | `roster.html:346` |
| 现象 | 渲染模板中 `<span class="card__avatar">${r.emoji}</span>` 直接输出 `r.emoji`，**未调用 `esc()`**。同模板内 name/title/animal/duty/color/tier 六个字段均经 `esc()` 转义，唯独 emoji 遗漏。 |
| 风险 | 代码注释（:322）明写「HTML 转义，防注入」，但 emoji 字段绕过了防护。当前 ROLES 为内部可信数据，风险不暴露；一旦数据源被污染（如 emoji 字段被改为 `<img src=x onerror=alert(1)>`），即可触发存储型 XSS。属"安全网有一处破洞"。 |
| 复现（推演） | 把任一角色 `emoji:'🐻'` 改为 `emoji:'<img src=x onerror=alert(1)>'`，页面加载即弹窗。 |
| 修复建议 | `${esc(r.emoji)}` |

> 等等等等，这块还得再测测——光头强哥写了 `esc()` 又留了个口子，我觉得这就是个雷。

### Bug #2 ｜ 卡片色条方向与需求/注释均不符（应为左侧，实为顶部）

| 项 | 内容 |
|----|------|
| 严重等级 | **P1 严重** |
| 类型 | 需求偏离 / 注释不符 |
| 位置 | `roster.html:139-145`（注释+CSS），关联 `roster-spec.md:52,222` |
| 现象 | ① **需求** `roster-spec.md` 两处明确：「左侧 4px 色条 `--role-color`」（:52、:222）。<br>② **注释** `roster.html:139` 也写「左侧色条：角色专属色」。<br>③ **实现** `roster.html:140-143` 却是 `height:4px; width:100%;` —— 这是卡片**顶部横条**，不是左侧竖条。 |
| 影响 | 实现、注释、需求三者不一致。若按"左侧"实现，应为 `width:4px; height:100%` 且 `.card` 改 `display:flex`，使 `.card__bar` 立于卡片左侧。当前顶部色条在视觉上未必难看，但**与设计意图相悖**。 |
| 修复建议 | 二选一：<br>① 改 CSS 为左侧竖条（符合需求与注释，推荐）；<br>② 或修订需求/注释为"顶部色条"并同步 spec。 |

> 我这儿好像有个问题…强哥你 spec 里白纸黑字写"左侧"，熊二却给画到顶上去了，到底听谁的？这必须打回去对齐！

### Bug #3 ｜ tier 字段无效值被静默丢弃

| 项 | 内容 |
|----|------|
| 严重等级 | **P2 中度** |
| 类型 | 健壮性 |
| 位置 | `roster.html:334` |
| 现象 | `ROLES.forEach(r => { if(buckets[r.tier]) buckets[r.tier].push(r); })` —— 若某角色 `tier` 拼错（如 `'Leader'` 大写、`'work'`、`'coder'`），`buckets[r.tier]` 为 `undefined`，该角色被**静默丢弃**，页面不报错、不提示，分组计数会悄悄少一个。 |
| 影响 | 数据录入错误时极难排查（"角色去哪了？"）。 |
| 修复建议 | 增加 `else` 分支：`console.warn('未知 tier:', r.tier, r.name)` 或直接抛错。 |

### Bug #5 ｜ font-weight 使用非标准值 650

| 项 | 内容 |
|----|------|
| 严重等级 | **P3 轻度** |
| 类型 | 代码规范 |
| 位置 | `roster.html:101`（`.group__head h2`） |
| 现象 | `font-weight:650;`。CSS 标准值为 100-900 **整百**或 normal/bolder/lighter。650 虽语法合法（Fonts Level 4 允许 1-1000），但大多数字体只提供 400/700 两档，650 会被映射到最接近的可用值（通常回落到 700），跨字体表现不一致。 |
| 修复建议 | 改为 `700`（或 `600`，若目标字体支持）。 |

---

### Bug #6 ｜ color-mix() 在旧浏览器失效（渐进增强）

| 项 | 内容 |
|----|------|
| 严重等级 | **P3 轻度** |
| 类型 | 兼容性 |
| 位置 | `roster.html:137, 194, 195, 196` |
| 现象 | 多处使用 `color-mix(in srgb, ...)`，需 Chrome 111+ / Safari 16.2+ / Firefox 113+。旧浏览器上 hover 边框色、层级标签底色将失效（可能回落为空值，导致标签无背景）。 |
| 影响 | 现代浏览器正常，属渐进增强问题；MVP 阶段可接受。 |
| 修复建议 | 为 `.card__tag--*` 补一条 fallback 背景色（如 `background:rgba(…,0.18)`），再写 color-mix 增强版。 |

### 4.4 放行建议

**结论：有条件放行（Conditional Pass）。**

理由：

- **功能完整性、语法、数据驱动、响应式布局均达标**，7 角色 4 要素三层分组完全符合需求，核心功能可用；
- **但存在 2 个 P1 严重缺陷必须先修复**：
  - Bug #1（emoji 未转义）破坏了代码自定的"防注入"安全网，属安全一致性硬伤；
  - Bug #2（色条方向）实现与需求/注释三方不一致，属需求偏离，影响交付可信度；
- P2 #3 建议同批修复（改动极小，1 行）；P3 四项可作为后续优化项。

**放行条件**：修复 Bug #1、Bug #2（必要时 #3）后，回归测试通过即可放行。P3 项不阻塞发布。
