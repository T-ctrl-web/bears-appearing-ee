# 熊出没集团 — 经验记忆主题索引

## security
- exp-001 [demo-001]: 动态内容（emoji等）必须调用 esc() 转义，否则存在 XSS 风险

## parallel
- exp-002 [demo-001]: 测试（蹦蹦）和文档（肥波）步骤可并行，都只依赖开发（熊二）产出

## verification
- exp-003 [demo-001]: Level 1 柔性审查发现 P1 安全问题也应修复，柔性不等于放任

## code-quality
- exp-004 [demo-001]: 注释与实现必须保持一致，避免误导后续维护者
- exp-005 [demo-001]: tier 等枚举值无效时应 console.warn 提示，不能静默丢弃

## roles
- exp-006 [demo-001]: 萝卜头（调试）适合修复单点遗漏型 Bug，挖洞式排查效率高
- exp-013 [demo2-001]: 14角色全员参与复杂任务验证：调研(毛毛)+架构(光头强)+开发(熊二)+界面(翠花)+测试(蹦蹦)+文档(肥波)+视觉(涂涂)+L2(老鳄)+L3(铁掌大师)+调试(萝卜头)+门禁(小狸)+运维(拖拖)全链路跑通

## security
- exp-007 [demo2-001]: 会话token必须校验（不能只查用户存在），否则攻击者可伪造session冒充任意用户
- exp-008 [demo2-001]: 密码哈希必须用PBKDF2等迭代算法（至少10万次），单次SHA-256可秒级破解
- exp-009 [demo2-001]: Storage.updateUser等敏感写操作必须有权限保护，防止控制台直接调用篡改密码

## parallel
- exp-010 [demo2-001]: 调研(毛毛)和架构(光头强)可并行——调研提供安全建议，架构提供技术设计，互为补充
- exp-011 [demo2-001]: 开发(熊二)和界面设计(翠花)可并行——都依赖架构方案，互不依赖
- exp-012 [demo2-001]: 测试+文档+视觉审查可三路并行——都依赖开发产出，互不依赖

## verification
- exp-014 [demo2-001]: L3强对抗审查（铁掌大师）能发现L2（老鳄）遗漏的严重漏洞——Storage.updateUser无权限保护和密码哈希强度不足
- exp-015 [demo2-001]: 驳回重跑机制有效——第1轮驳回13项问题，萝卜头修复后第2轮门禁确认P0/P1全部修复
- exp-016 [demo2-001]: 文档与代码不一致是质量门禁的常见阻断项——升级密码算法后必须同步更新spec和README

## cost-control
- exp-017 [demo2-001]: 复杂任务（14角色）实际消耗12个subagent，需提前调整单任务上限（从5调到12）
