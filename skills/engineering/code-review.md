# Skill: code-review — 代码审查

## 用途

对代码产出做结构化审查，由吉吉国王（代码质检）和光头强（架构审查）使用。

## 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| target_files | array | 是 | 待审查文件路径列表 |
| task_requirements | string | 是 | 原始任务要求 |
| tech_spec | string | 否 | 技术方案（如有） |
| review_level | number | 否 | 审查级别 1/2/3，默认 1 |

## 审查维度

### Level 1 — 柔性审查（MVP 默认）
1. **完整性** — 产出是否覆盖任务要求的所有功能点
2. **语法正确性** — 是否有明显的语法错误、拼写错误
3. **边界覆盖** — 关键边界情况是否处理
4. **格式规范** — 代码风格、命名规范、文件组织

### Level 2 — 标准审查（Phase 2）
5. **代码风格一致性** — 与项目现有代码风格是否统一
6. **性能评估** — 是否有明显的性能问题
7. **可维护性** — 是否易于理解和修改
8. **安全基础** — 是否有常见安全漏洞（XSS、SQL注入等）

### Level 3 — 强对抗审查（Phase 2）
9. **极端边界测试** — 构造极端输入验证鲁棒性
10. **架构合理性质疑** — 质疑设计决策的合理性
11. **故意构造异常** — 模拟异常场景

## 输出格式

```
## 审查报告

### 基本信息
- 审查人：{reviewer_name}
- 审查目标：{target_files}
- 审查级别：Level {n}
- 任务要求：{task_requirements}

### 审查清单
| 检查项 | 结果 | 备注 |
|--------|------|------|
| 完整性 | ✅/❌ | {说明} |
| 语法正确性 | ✅/❌ | {说明} |
| 边界覆盖 | ✅/❌ | {说明} |
| 格式规范 | ✅/❌ | {说明} |

### 问题列表
| # | 文件 | 行号 | 问题 | 严重度 | 建议 |
|---|------|------|------|--------|------|

### 结论

- [ ] 建议修改后放行（附修改建议）
- [ ] 建议驳回重跑
```
