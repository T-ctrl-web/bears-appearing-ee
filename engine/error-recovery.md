# 核心机制：错误恢复

## 用途

检测 Worker 执行失败、超时、产出异常等情况，按策略自动恢复或升级用户。

## 错误类型与处理

| 错误类型 | 检测方式 | 首次处理 | 第二次处理 | 第三次处理 |
|----------|----------|----------|------------|------------|
| Worker 超时 | 步骤执行 > 120s | 同角色重试 | 换角色重试 | 升级用户 |
| Worker 失败 | subagent 返回错误 | 同角色重试 | 换角色重试 | 升级用户 |
| 产出异常 | 产出为空/格式不符 | 驳回重做 | 换角色重做 | 升级用户 |
| Verifier 超时 | 审查 > 60s | 默认放行+标注 | — | — |
| 验证驳回超限 | 迭代 >= max | 升级用户 | — | — |
| subagent 超限 | 计数 >= 上限 | 暂停+问用户 | — | — |

## 重试策略

### 同角色重试（第一次）
```
Worker 执行失败
  ↓
总裁判断失败原因：
  - 可恢复错误（超时/临时失败）→ 同一角色重新派发，调整 prompt
  - 不可恢复错误（角色能力不足）→ 直接换角色
  ↓
重试时调整：
  - 简化任务描述
  - 提供更多上下文
  - 降低产出要求（先跑通再优化）
```

### 换角色重试（第二次）
```
同角色重试仍失败
  ↓
换一个角色执行：
  - 开发失败 → 换调试角色排查
  - 测试失败 → 换开发角色自测
  - 架构失败 → 换调研角色先调研再设计
  ↓
换角色时说明：
  "原执行人 [角色A] 执行 [任务] 失败（原因：X）
   换 [角色B] 重新执行，调整策略：[说明]"
```

### 升级用户（第三次）
```
两次重试均失败
  ↓
总裁输出失败报告：
  "任务执行失败（已重试 2 次）
   失败步骤：步骤 N — [任务描述]
   第一次失败：[角色A] — [原因]
   第二次失败：[角色B] — [原因]
   已尝试的策略：[列出]
   建议：[用户决策方向]"
  ↓
用户决策：
  - 手动修复 → 用户自行处理，总裁等待
  - 调整需求 → 修改任务要求后重试
  - 放弃 → 标记任务失败
```

## 产出异常检测

总裁在收到 Worker 产出后，检查：
1. 产出文件是否存在
2. 产出内容是否为空
3. 产出格式是否符合角色定义的输出规范
4. 产出是否覆盖了任务要求的关键功能点

如检测到异常，不派发 Verifier，直接驳回重做。

## 错误记录

每次错误恢复都记录到会话记忆：
```json
{
  "error_type": "worker_timeout/worker_failed/output_abnormal",
  "step": N,
  "worker": "[角色名]",
  "retry_count": X,
  "recovery_strategy": "same_role/switch_role/escalate",
  "resolution": "success/failed/user_decision"
}
```
