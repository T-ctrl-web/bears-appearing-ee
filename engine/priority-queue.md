# 核心机制：优先级队列

## 用途

管理多个待执行任务的排队顺序，确保紧急任务优先处理。

## 优先级定义

| 级别 | 名称 | 判断条件 | 处理方式 |
|------|------|----------|----------|
| P0 | 紧急 | 线上故障、安全漏洞、数据丢失 | 立即插队，暂停当前任务 |
| P1 | 常规 | 功能开发、Bug修复、正常需求 | 正常排队执行 |
| P2 | 后台 | 文档优化、技术债、代码美化 | 空闲时执行，不阻塞 P1 |

## 排队规则

### 插队逻辑
```
新任务到达 → 判断优先级
  P0 → 暂停当前执行中的任务（记录断点），立即开始 P0 任务
  P1 → 加入 P1 队列尾部，等待当前任务完成后执行
  P2 → 加入 P2 队列，仅当 P1 队列为空时执行
```

### 出队逻辑
```
每次出队时：
  1. P0 队列非空 → 取 P0 队首
  2. P0 为空，P1 队列非空 → 取 P1 队首
  3. P0/P1 均空，P2 队列非空 → 取 P2 队首
  4. 全空 → 空闲，等待新任务
```

## P0 暂停与恢复

当 P0 任务到达时，暂停当前任务：
1. 记录当前任务的执行断点（当前步骤、已完成步骤、待完成步骤）
2. 将暂停任务放回 P1 队列头部（恢复时优先）
3. 执行 P0 任务
4. P0 完成后，从 P1 队列头部取出暂停的任务，从断点恢复

## Phase 2 限制

- TRAE 单会话是单线程的，优先级队列本质是排序——决定先做哪个后做哪个
- 真正的多任务并行需要 Phase 3 的 DeepSeek harness
- P0 暂停后恢复在同一会话内完成；跨会话的恢复需要 Phase 3

## 输出格式

总裁收到新任务时输出：

```
## 优先级判定

- 任务：[描述]
- 判定优先级：P0/P1/P2
- 理由：[判断依据]
- 当前队列状态：
  P0: [X个任务]
  P1: [X个任务]
  P2: [X个任务]
- 执行决策：立即执行/排队等待/空闲时执行
```
