# 核心机制：成本控制

## 用途

在任务执行过程中，实时监控 subagent 数量和验证迭代次数，超限时暂停并通知用户。

## 监控指标

| 指标 | 上限 | 计数方式 | 超限处理 |
|------|------|----------|----------|
| 单任务 subagent 数 | 5 | 每派发一个 Worker/Verifier +1 | 暂停派发，输出进度，问用户 |
| 单会话 subagent 数 | 15 | 跨任务累计 | 暂停派发，输出进度，问用户 |
| 单任务 token 预算 | 500000 | 每次 API 调用累加 total_tokens | 暂停派发，输出用量，问用户 |
| 单会话 token 预算 | 2000000 | 跨任务累计 | 暂停派发，输出用量，问用户 |
| 验证迭代（L1） | 1 | 每驳回重跑 +1 | 升级用户决策 |
| 验证迭代（L2） | 2 | 每驳回重跑 +1 | 升级用户决策 |
| 验证迭代（L3） | 3 | 每驳回重跑 +1 | 升级用户决策 |
| Worker 超时 | 120s | 单步执行时间 | 标记超时，触发错误恢复 |
| Verifier 超时 | 60s | 单次审查时间 | 标记超时，默认拒绝并标注 |
| Verifier 调用失败 | — | API 错误/网络异常 | 默认拒绝，记录错误，升级用户 |

## 超限处理流程

### subagent 超限
```
检测到 subagent 数 >= 上限
  ↓
总裁输出：
  "成本提醒：subagent 数已达上限（X/Y）
   当前进度：步骤 N/M
   已完成：[列出已完成步骤]
   待完成：[列出待完成步骤]
   是否追加预算？"
  ↓
等待用户决策：
  追加 → 上限 +5，继续执行
  拒绝 → 暂停，保留当前进度
```

### 验证迭代超限
```
检测到验证迭代 >= max_iterations
  ↓
Verifier 输出终审失败报告：
  "终审失败（Level X，第 N 轮）
   未通过项：[列出]
   建议：[修复方向]"
  ↓
升级用户决策：
  强制放行 → 总裁标注"用户强制放行"后交付
  继续重试 → 追加 1 轮迭代（需用户确认）
  放弃 → 标记任务失败
```

## 预算估算

总裁在拆解任务后，输出预估成本：

```
## 成本预估

- 预计 subagent 数：X（Y 个 Worker + Z 个 Verifier）
- 预计验证迭代：1-2 轮
- 单任务预算：X/5 subagent
- 风险提示：[如有超限风险]
```
