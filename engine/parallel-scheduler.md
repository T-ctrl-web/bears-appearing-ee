# 核心机制：并行调度

## 用途

熊大（总裁）拆解任务后，按此逻辑判断哪些步骤可并行、哪些必须顺序执行，并控制并行度。

## 并行判断规则

### 可并行的条件
1. 两个步骤之间**无依赖关系**（步骤 B 不需要步骤 A 的产出作为输入）
2. 两个步骤操作**不同的文件或目录**（不会产生写冲突）
3. 两个步骤**由不同角色执行**（不会资源冲突）

### 必须顺序的条件
1. 步骤 B 依赖步骤 A 的产出（如开发依赖架构方案）
2. 两个步骤操作同一文件
3. 步骤 B 是步骤 A 的验证（验证必须在产出之后）

## 并行度控制

| 配置项 | 值 | 说明 |
|--------|-----|------|
| max_concurrent | 3 | 最多同时 3 个 subagent |
| 超限策略 | 排队等待 | 超过 3 个时排队，先完成先出队 |

## 调度算法

```
1. 将所有步骤构建为 DAG（有向无环图），边表示依赖
2. 拓扑排序，找出所有入度为 0 的节点（可执行步骤）
3. 从可执行步骤中取 min(可执行数, max_concurrent) 个并行派发
4. 等待任一步骤完成
5. 移除已完成步骤，更新其后继节点的入度
6. 新的入度为 0 的节点加入可执行队列
7. 回到步骤 3，直到全部完成
```

## 示例

```
步骤1: 光头强设计架构（无依赖）
步骤2: 毛毛调研竞品（无依赖）          ← 与步骤1并行
步骤3: 熊二实现代码（依赖步骤1）
步骤4: 翠花设计界面（依赖步骤1）        ← 与步骤3并行
步骤5: 蹦蹦测试（依赖步骤3和步骤4）
步骤6: 肥波写文档（依赖步骤3）          ← 与步骤5并行
步骤7: 吉吉国王审查（依赖步骤3）

并行执行波次：
  波次1: [步骤1, 步骤2]          → 2个并行
  波次2: [步骤3, 步骤4]          → 2个并行
  波次3: [步骤5, 步骤6, 步骤7]   → 3个并行
```
