# 核心机制：复杂度评估

## 用途

熊大（总裁）接收需求后，按此逻辑评估任务复杂度，决定走快速通道还是拆解派发，以及选择验证级别。

## 评估维度

| 维度 | 简单 | 中等 | 复杂 |
|------|------|------|------|
| 涉及文件数 | 1 | 2-5 | >5 |
| 涉及模块数 | 1 | ≤2 | >2 |
| 依赖关系 | 无 | 顺序依赖 | 交叉依赖 |
| 技术栈数量 | 1 | 2 | 3+ |
| 安全敏感度 | 无 | 普通 | 涉及认证/数据/支付 |
| 是否跨系统 | 否 | 否 | 是 |

## 评估规则

```
得分 = 文件数权重(30%) + 模块数权重(25%) + 依赖关系权重(15%)
     + 技术栈权重(10%) + 安全敏感度权重(15%) + 跨系统权重(5%)

简单：得分 ≤ 30 → 快速通道
中等：30 < 得分 ≤ 65 → 拆解顺序执行 + Level 1 验证
复杂：得分 > 65 → 拆解 + 并行派发 + Level 2/3 验证
```

## 快速判断（总裁用）

| 判断条件 | 结果 |
|----------|------|
| 改文案/修拼写/改配置 | 简单 → 快速通道 |
| 单文件加功能/修Bug | 简单 → 快速通道 |
| 新功能开发（单模块） | 中等 → 拆解 + L1 |
| 多文件改动/新模块 | 中等 → 拆解 + L1 |
| 跨模块/系统级改动 | 复杂 → 拆解 + 并行 + L2 |
| 涉及安全/认证/数据 | 复杂 → 拆解 + L3（铁掌大师） |

## 验证级别映射

| 复杂度 | 验证级别 | Verifier | 最大迭代 |
|--------|----------|----------|----------|
| 简单 | 无 | 总裁自审 | 0 |
| 中等 | Level 1 | 吉吉国王 | 1 |
| 复杂（普通） | Level 2 | 老鳄 + 小狸 | 2 |
| 复杂（安全敏感） | Level 3 | 铁掌大师 | 3 |

## 输出格式

总裁评估后输出：

```
## 复杂度评估

- 涉及文件数：X
- 涉及模块数：X
- 依赖关系：[无/顺序/交叉]
- 安全敏感度：[无/普通/敏感]
- 综合得分：X
- 判定：简单/中等/复杂
- 处理方式：快速通道/拆解顺序/拆解并行
- 验证级别：无/L1/L2/L3
- 分配 Verifier：[无/吉吉国王/老鳄+小狸/铁掌大师]
```
