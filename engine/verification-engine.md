# 验证引擎：三级验证 + 驳回重跑

## 验证流程

```
Worker 完成产出
  ↓
总裁检查产出异常（空/格式不符/未覆盖关键点）
  ├─ 异常 → 直接驳回重做（不经 Verifier）
  └─ 正常 → 派发 Verifier
        ↓
        Verifier 按验证级别审查
        ├─ Level 1 柔性 → 提建议，可放行
        ├─ Level 2 标准 → 通过 或 驳回（迭代 ≤ 2）
        └─ Level 3 强对抗 → 通过 或 驳回（迭代 ≤ 3）
              ↓
              通过 → 总裁汇总交付
              驳回 → 总裁重新派发 Worker（迭代 +1）
                    ↓
                    迭代 < max → Worker 重做 → Verifier 再审
                    迭代 = max → 终审失败 → 升级用户
```

## Level 1 柔性审查（吉吉国王）

- **心态**：友善提建议，不挑刺
- **通过标准**：基本功能点全覆盖，无语法错误
- **驳回标准**：几乎不驳回（柔性）
- **最大迭代**：1 次
- **输出**：审查清单 + 建议 + 结论（建议放行/建议修改后放行）

## Level 2 标准审查（老鳄 + 小狸）

- **心态**：专业质检官，发现问题就驳回
- **通过标准**：全部审查项通过，无 P1/P2 问题
- **驳回标准**：有 P1 问题必驳回，P2 问题视情况
- **最大迭代**：2 次
- **分工**：
  - 老鳄：设计层面审查（架构、接口、可扩展性）
  - 小狸：质量门禁（需求覆盖、测试充分、交付完整）
- **输出**：审查清单 + 问题列表 + 结论（通过/驳回重跑/终审失败）

## Level 3 强对抗审查（铁掌大师）

- **心态**：挑刺、对抗，故意构造攻击
- **通过标准**：全部安全检查项通过，无任何安全漏洞
- **驳回标准**：任何安全漏洞必驳回
- **最大迭代**：3 次
- **审查方式**：
  - 主动构造攻击向量
  - 故意输入恶意数据
  - 尝试绕过验证逻辑
  - 质疑安全架构设计
- **输出**：安全审查清单 + 漏洞列表 + 攻击面分析 + 结论

## 驳回重跑机制

### 驳回触发
- Level 1：几乎不触发（柔性）
- Level 2：P1 问题 或 P2 问题累计 ≥ 3
- Level 3：任何安全漏洞

### 重跑流程
```
Verifier 输出驳回结论
  ↓
总裁记录：迭代次数 +1
  ↓
总裁判断：
  迭代 < max → 重新派发 Worker，附带驳回报告和修改建议
  迭代 = max → 输出终审失败报告，升级用户
  ↓
Worker 重做时：
  - 必须收到驳回报告（知道上次哪里不对）
  - 必须针对被驳回的问题修改
  - 不能只改驳回项，要回归自测
```

### 终审失败处理
```
迭代达到 max 仍未通过
  ↓
Verifier 输出终审失败报告：
  "终审失败（Level X，第 N 轮）
   持续未通过项：[列出]
   已尝试修复：[列出各轮修改]
   建议：[最终方向]"
  ↓
总裁升级用户：
  "验证终审失败，需要你决策：
   A. 强制放行（标注'未通过验证'）
   B. 追加 1 轮迭代
   C. 放弃任务"
```
