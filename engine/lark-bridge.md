# 飞书桥接引擎

## 用途

连接飞书 IM 和熊出没集团，实现用户通过飞书派发任务、接收进度通知、获取最终交付。

## 工作流程

```
用户飞书发消息
  ↓
飞书事件回调 → 熊大接收
  ↓
秒回确认（3秒内）
  ↓
熊大评估复杂度 + 拆解任务
  ↓
飞书推送拆解表（交互卡片）
  ↓
开始执行（波次调度）
  ↓
每个波次完成 → 飞书推送进度
  ↓
全部完成 → 飞书推送交付通知
```

## 秒回机制

### 触发条件
飞书事件回调收到用户消息后，3秒内必须回复，否则飞书超时。

### 秒回内容
```
收到！我是熊大（总裁）。
你说的任务是：[复述用户消息]
正在评估复杂度，稍后给你拆解结果。
```

### 实现
利用 Lark 插件的 IM 能力：
1. 监听飞书消息事件（lark-event consume）
2. 收到消息后立即发送秒回
3. 后台开始评估和拆解

## 消息解析规则

### 纯文本消息
直接作为任务描述，传给熊大评估。

### 富文本消息
提取正文内容，忽略格式标记。

### 文件消息
下载文件，读取内容，作为任务上下文。

### 模糊需求
如果消息太模糊（如"帮我做个东西"），追问：
```
毛毛（调研）想了解更多：
1. 你想做什么类型的东西？
2. 有什么参考吗？
3. 需要什么功能？
```

```

已完成：
✅ 步骤1: 拖拖 — 脚手架搭建
✅ 步骤2: 毛毛 — 安全调研
✅ 步骤3: 光头强 — 架构设计

进行中：
⏳ 步骤4: 熊二 — 代码实现
⏳ 步骤5: 翠花 — 界面设计

待执行：
⬜ 步骤6: 蹦蹦 — 测试
⬜ 步骤7: 吉吉国王 — 审查
```

### 驳回通知
```
[验证驳回]

{Verifier} 驳回了 {Worker} 的产出：
问题数：X
严重度分布：严重X / 高X / 中X / 低X

```

### 交付通知
```
[任务完成]

交付物：
1. {文件名} — {说明}
2. {文件名} — {说明}

查看详情：{computer://链接}
```

## 交互卡片设计

飞书交互卡片包含：
- **头部**：熊出没集团 logo + 任务标题
- **进度区**：当前波次 / 总波次 + 进度条
- **角色区**：14 个角色头像 + 状态标记（空闲/执行中/完成）
- **按钮区**：查看详情 / 暂停任务 / 取消任务

## Lark 插件调用

通过 TRAE 的 Lark 插件实现：
1. `lark-im` — 收发消息
2. `lark-event` — 监听消息事件
3. `lark-contact` — 解析用户身份
4. `lark-drive` — 发送文件交付
